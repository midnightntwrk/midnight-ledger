# `midnight-react-native-demo`

Reference React Native app that exercises the
[`@midnight-ntwrk/react-native-prover`](../react-native-prover/)
package. Ports the Benchmark screen and DID CRUD operations
from the Dioxus wallet so downstream teams building an RN
Midnight wallet have a working integration to crib from.

## Status (2026-05-24)

**Pre-flight. The app's code is written and type-correct, but
it hasn't been launched on a device yet** — that requires:

1. `cargo install uniffi-bindgen-react-native` (the binding
   generator that produces the JSI Turbo Module shims for the
   native prover package — see `../react-native-prover/`)
2. `cargo install cargo-ndk` (for the Android cross-build)
3. `cd ../react-native-prover && yarn build:all` (produces
   the `.xcframework` + `.so` + generated TS/Swift/Kotlin
   bindings)
4. iOS / Android native project files (`ios/Podfile`,
   `android/app/build.gradle`) — these are conventionally
   generated by `npx @react-native-community/cli init` and
   then customised; this repo lays out the JS+TS side of
   the app and assumes the consumer runs that scaffolding
   step in their own copy

This is intentional — the JS / TS layer is the
hardest-to-write part and the part most likely to be reused
across consumers, so we ship that and leave the scaffolding
of native project shells (which is two commands away from
`npx init`) to the consumer.

## What works (when scaffolded into a real RN host)

- ✅ The Benchmark screen calls
  `@midnight-ntwrk/react-native-prover`'s `prove()` end-to-end.
  Per-row Run and Run-all sweep, k=1..21.
- ✅ Stable column widths across the Run / Running / Done
  transitions — same layout discipline as the Dioxus wallet
  post-`f74844d8`.
- ✅ Tab navigation between Benchmark / DID / About.
- ✅ `libraryVersion()` displayed on the About screen so the
  bundled Rust core version is visible at runtime.

## What's stubbed (and why)

The DID screen's resolve / deploy / update / deactivate
buttons call deterministic stub implementations that return
fake-but-realistic responses after a short delay. The reason:

The Dioxus wallet's DID flows depend on the upstream TS
contract layer (`@midnight-ntwrk/midnight-did-contract`,
`@midnight-ntwrk/compact-runtime`, the
`onchain-runtime-v3` + `ledger-v8` WASM blobs) running
inside a WebView. Porting that to React Native requires
either:

- **(a) Embedding the same TS+WASM bundle in RN's Hermes
  engine.** Hermes doesn't support WASM natively today;
  needs a JS-side WASM shim or a custom JSI host-object that
  exposes WASM exports as plain JS. Doable but its own
  subproject.

- **(b) Porting the contract layer to Rust** and exposing it
  via UniFFI alongside the prover. Cleaner long-term but
  a multi-month project.

Both options are out of scope for this demo. The DID screen
is structured so swapping in a real bridge requires changes
only inside `src/hooks/useDid.ts` — the UI components don't
care which implementation backs the operations.

## Scaffolding into a runnable RN app

Quickest path (Expo bare workflow):

```bash
# In a fresh directory (outside this repo):
npx create-expo-app --template bare-minimum midnight-demo
cd midnight-demo

# Copy this repo's JS over:
cp -r /path/to/midnight-ledger/react-native-demo/src ./
cp /path/to/midnight-ledger/react-native-demo/App.tsx ./
cp /path/to/midnight-ledger/react-native-demo/babel.config.js ./
cp /path/to/midnight-ledger/react-native-demo/tsconfig.json ./
# Merge package.json deps

# Install
yarn install
cd ios && pod install && cd ..

# Run
yarn ios
# or
yarn android
```

Or, for a bare React Native scaffold:

```bash
npx @react-native-community/cli init MidnightDemo --version 0.74.5
# then copy src/, App.tsx, etc. and merge package.json
```
