# Passport-Vault dApp integration (lock / claim)

This wallet hosts the **passport-vault dApp** in an iframe (loaded from
`MIDNIGHT_DAPP_URL`) and drives the vault's **multi-lock** circuits —
`createLock`, `depositToLock`, `claimFromLock`, `withdrawFromLock` — through
the same compose → balance → prove → submit pipeline the DID contract uses.
Lock pools hold native **unshielded** NIGHT.

```
passport-vault dApp (iframe; loaded from MIDNIGHT_DAPP_URL)
  └─ window.midnight host shim ──postMessage──▶ relay (lib.rs head)
                                                  └─ window.midnightWallet.<verb>(...)
                                                       └─ Rust bridge (bridge.rs dispatch)
                                                            └─ app_vault_wallet_for(net) → Wallet vault verbs (wallet.rs)
   compose (in-WebView): window.midnightDidBundle.prepareVaultCallTx / prepareVaultClaim (entry.ts)
   prove/submit:        Wallet::call_contract_circuit (wallet.rs) + vault prover keys
                        (vault/artifacts.rs, resolved in tx/prove.rs)
```

## Assets that must be present before building

### 1. WebView JS bundle + vendored packages

`assets/web/midnight-did.js` and `assets/web/pkg/` are baked into the Rust
binary via `include_str!` / `include_dir!` (`src/lib.rs` + `src/protocol.rs`),
so they must exist before `cargo build`. Produced by the `web/` package's
`npm run build` (runs `vendor.mjs` then `build.mjs`). `vendor.mjs` also vendors
the passport-vault contract into:

- `assets/web/pkg/passport-vault-contract/dist/` (incl.
  `managed/passport-vault/{keys,zkir}` — the prover/verifier/zkir blobs the
  WebView ZK config provider fetches over `mn-pkg://`).

Source package: `@input-output-hk/passport-vault-contract` at
`midnight-identity-solution-examples/packages/contracts/vault` (already compiled
in-repo). Rebuild only if you change the contract:
`npm run build -w @input-output-hk/passport-vault-contract` from
`midnight-identity-solution-examples/`.

### 2. Native (Rust) circuit artifacts — generated by `cargo build`

`wallet-core/contracts/{midnight-did,passport-vault}/<circuit>.{prover,verifier,bzkir,zkir}`
are embedded via `include_bytes!` (`wallet-core/src/{did,vault}/artifacts.rs`).
**This `contracts/` tree is gitignored and regenerated on every `cargo build`
by `wallet-core/build.rs`** — no external script needed. It flattens each
contract's `managed/<contract>/{keys,zkir}` source tree into the embed layout,
and re-syncs whenever the sources change or `contracts/` is deleted. Sources
default to the sibling submodules:

- DID: `midnight-did/packages/contract/src/managed/did` (override
  `MIDNIGHT_DID_MANAGED_DIR`).
- passport-vault:
  `midnight-identity-solution-examples/packages/contracts/vault/src/managed/passport-vault`
  (override `MIDNIGHT_VAULT_MANAGED_DIR`).

Building wallet-core therefore requires those contract sources present (or the
override env vars set).

### 3. dApp UI — loaded from a URL

The Vault dApp tab loads the dApp in an iframe from `MIDNIGHT_DAPP_URL` (default
`http://localhost:3000`, the Next.js dev server). There is no bundled static
export — point the env var at a running dApp:

```bash
# dev: run the dApp's Next.js server, then launch the wallet
( cd midnight-identity-solution-examples && npm run dev -w @input-output-hk/passport-vault-dapp )
MIDNIGHT_DAPP_URL=http://localhost:3000 ./scripts/run-demo.sh launch-desktop
# or a deployed URL
MIDNIGHT_DAPP_URL=https://vault.example.com ./scripts/run-demo.sh launch-desktop
```

## Build + run commands

```bash
# Prereqs: Node 24 (nvm use 24), MIDNIGHT_DID_SRC pointing at a built
# midnight-did checkout (defaults to the repo submodule), proof-server
# image + standalone env for on-chain ops.

export MIDNIGHT_DID_SRC="$PWD/midnight-did"        # if not using the Nix devshell

# Build the WebView bundle (vendor + esbuild):
( cd midnight-ledger/mobile-bench/dioxus-wallet/web && npm install && npm run build )

# Desktop wallet (release) + launch — via the demo orchestrator:
./scripts/run-demo.sh build-desktop
./scripts/run-demo.sh launch-desktop      # log: /tmp/midnight-ssi-wallet.log

# Full standalone demo env (node + indexer + proof server + issuer):
./scripts/run-demo.sh up                  # then launch-desktop

# Point the Vault dApp tab at the dApp URL (default http://localhost:3000):
MIDNIGHT_DAPP_URL=http://localhost:3000 ./scripts/run-demo.sh launch-desktop
```

`run-demo.sh build-desktop` runs `build_wallet_js_bundle` (the WebView bundle)
before `cargo build -p dioxus-wallet --release`. The Vault dApp itself is served
separately and loaded via `MIDNIGHT_DAPP_URL` at runtime — nothing dApp-related
is bundled into the wallet binary.

## What is wired

- **Vault prover keys** — vendored contract (`vendor.mjs`) + native keys
  (`vault/artifacts.rs`, resolved in `tx/prove.rs`).
- **WebView compose** — `prepareVaultCallTx` (generic circuit) + `prepareVaultClaim`
  (deserialise credential bundle → lock policy → selective-disclosure
  presentation → `claimFromLock`) in `web/src/entry.ts` (+ Node mirror in the
  test harness).
- **Native pipeline** — `Wallet::call_contract_circuit` (`wallet.rs`) + the
  multi-lock verbs `create_lock`, `deposit_to_lock`, `claim_from_lock`,
  `vault_total_locked`, `list_locks`.
- **Connector transport** — dApp host shim
  (`midnight-identity-solution-examples/apps/dapp/lib/midnight/mobile-bench-host.ts`),
  the postMessage relay (`lib.rs` head), and the bridge `dispatch` (`bridge.rs`),
  all routed through an app-owned `Wallet` via `app_vault_wallet_for(net)`.
  Exposed `window.midnightWallet.*` surface: `getConfiguration`, `vaultCreateLock`,
  `vaultDeposit`, `vaultClaim`, `vaultListLocks`, `vaultListCredentials`,
  `vaultTotalLocked`.
- **Dapp screen** — a `Tab::Dapp` ("Vault dApp") tab in `src/app.rs` renders the
  dApp in an iframe; the `src` comes from `dapp_url()` — `MIDNIGHT_DAPP_URL` if
  set, else the `http://localhost:3000` default. The dApp is always loaded from a
  URL; nothing is bundled.

Remaining follow-ups (see the inline notes around the `vaultClaim` arm in
`bridge.rs` and the vault verbs in `wallet.rs`): the lock/claim verbs are wired
end-to-end, but `vaultClaim` still depends on the holder selecting a stored
credential (`vcUri`) and on the lock-policy / presentation details being driven
from the dApp UI.

## Networks / proving notes

- Lock pools hold native **unshielded** NIGHT. `createLock` / `depositToLock`
  are funded from the running wallet's unshielded NIGHT (creator-only on-chain).
  `claimFromLock` pays the released NIGHT to the claimer's unshielded address and
  needs no shielded sync — the holder only covers DUST fees.
- Dev on `undeployed` (standalone env) first: fast sync + proving. On PreProd,
  dust sync + multi-circuit claim proving are slow (minutes).
- The vault address resolves from a per-call `contractAddress` param, else the
  `MIDNIGHT_VAULT_CONTRACT_ADDRESS` env var, else the preprod default (see
  `vault_contract_address` in `bridge.rs`).
